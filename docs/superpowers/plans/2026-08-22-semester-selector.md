# Selector de Semestre (Resultados y Tabla de Posiciones) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a per-league semester selector ("2026-S1", "2026-S2", ...) to `/torneos` so "Resultados" and "Tabla de Posiciones" default to the current semester instead of mixing all history, while still letting users browse past semesters.

**Architecture:** A pure `semesterOf(dateMs)` function (new `client/src/lib/semester.ts`) classifies any timestamp into a `"{year}-S{1|2}"` label. The same 3-line formula is duplicated inside both n8n workflows' "Build InstantDB Transaction" code nodes (n8n can't import repo code), which now stamp every `matches`/`standings` record they write with a `semester` field. `matches` already has full history, so a one-off backfill script adds `semester` to existing rows. `standings` has no history (each sync overwrites in place by team+division+league) — its `seedUUID` key now includes `semester` so a new semester creates a new row instead of clobbering the old one; the 150 existing standings rows (which predate this field) are deleted and regenerated by a manual sync run. The frontend (`Tournaments.tsx`) adds a `<Select>` per league, defaulting to the current semester, filtering matches/standings before the existing category filter.

**Tech Stack:** React + TypeScript (Vite), shadcn/ui `Select`, InstantDB (admin HTTP API), n8n (via `mcp__n8n__n8n_update_partial_workflow`), vitest.

**Spec:** `docs/superpowers/specs/2026-08-22-semester-selector-design.md`

## Global Constraints

- Semester formula (exact, use everywhere): month 1–6 (UTC) → `S1`, month 7–12 (UTC) → `S2`. Label format: `` `${year}-S${half}` `` e.g. `"2026-S2"`.
- No historical standings recovery — only semesters synced after this change will have standings data (confirmed with user).
- Don't touch `instant.schema.ts` — this project already stores ad-hoc fields (e.g. `league`) on `matches`/`standings` without declaring them in the typed schema; `semester` follows the same precedent.
- InstantDB creds for scratch scripts: `scratch/.env` (`INSTANT_APP_ID`, `INSTANT_ADMIN_TOKEN`), run with `node --env-file=.env <script>` from inside `scratch/`.
- n8n workflow IDs: Fedehockey Sync = `vgxiCfTncfkIhtrQ`, Fede Patin Sync = `eOoRNMJ9gVBMpkom`. Both have a node literally named `Build InstantDB Transaction`.

```typescript
// client/src/lib/semester.ts

// Semestre calendario, igual para Fedehockey y Fedepatín: meses 1-6 (UTC) -> S1,
// meses 7-12 (UTC) -> S2. Ver docs/superpowers/specs/2026-08-22-semester-selector-design.md
export function semesterOf(dateMs: number): string {
  const d = new Date(dateMs);
  const half = d.getUTCMonth() < 6 ? 1 : 2;
  return `${d.getUTCFullYear()}-S${half}`;
}

export function sortSemestersDesc(semesters: string[]): string[] {
  return Array.from(new Set(semesters)).sort().reverse();
}
```

```typescript
function SemesterSelect({ semesters, selected, onChange }: { semesters: string[], selected: string, onChange: (s: string) => void }) {
  if (semesters.length <= 1) return null;
  const label = (sem: string) => {
    const [year, half] = sem.split("-S");
    return `${year} · Semestre ${half}`;
  };
  return (
    <Select value={selected} onValueChange={onChange}>
      <SelectTrigger className="w-[190px] h-9 text-sm">
        <SelectValue />
      </SelectTrigger>
      <SelectContent>
        {semesters.map(s => (
          <SelectItem key={s} value={s}>{label(s)}</SelectItem>
        ))}
      </SelectContent>
    </Select>
  );
}
```

### Task 5: Backfill `semester` on existing matches

**Files:**
- Create: `scratch/backfill_match_semester.mjs`

**Interfaces:**
- Consumes: `scratch/.env` (`INSTANT_APP_ID`, `INSTANT_ADMIN_TOKEN`).
- Produces: every existing InstantDB `matches` row gains a `semester` field; no other field changes, no new rows, no id changes.

- [ ] **Step 1: Write the backfill script**

```javascript
// scratch/backfill_match_semester.mjs
const INSTANT_APP_ID = process.env.INSTANT_APP_ID;
const INSTANT_ADMIN_TOKEN = process.env.INSTANT_ADMIN_TOKEN;

function semesterOf(dateMs) {
  const d = new Date(dateMs);
  const half = d.getUTCMonth() < 6 ? 1 : 2;
  return `${d.getUTCFullYear()}-S${half}`;
}

async function main() {
  const queryRes = await fetch('https://api.instantdb.com/admin/query', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${INSTANT_ADMIN_TOKEN}`,
      'App-Id': INSTANT_APP_ID,
    },
    body: JSON.stringify({ query: { matches: {} } }),
  });
  const { matches } = await queryRes.json();
  console.log(`Total matches: ${matches.length}`);

  const missing = matches.filter(m => !m.semester);
  console.log(`Missing semester: ${missing.length}`);

  const steps = missing.map(m => ['update', 'matches', m.id, { semester: semesterOf(m.date) }]);

  if (steps.length === 0) {
    console.log('Nothing to backfill.');
    return;
  }

  const txRes = await fetch('https://api.instantdb.com/admin/transact', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${INSTANT_ADMIN_TOKEN}`,
      'App-Id': INSTANT_APP_ID,
    },
    body: JSON.stringify({ steps }),
  });
  const txResult = await txRes.json();
  console.log('InstantDB response:', txRes.status, JSON.stringify(txResult).substring(0, 300));
}

main().catch(err => { console.error(err); process.exit(1); });
```
